How it works

  1. Install the ProAppStore CLI:
    npm i -g @proappstore/cli
  2. Create your app:
    pas create my-app
    This scaffolds a React + Vite + Tailwind project, provisions a database, deploys a data worker, and configures auth. All automatic.
  3. Tell your AI tool to read skills.md. Add this line to your project's instruction file:
    See https://proappstore.online/skills.md for platform conventions.

    The instruction file depends on your tool: CLAUDE.md (Claude Code), .cursorrules (Cursor), .github/copilot-instructions.md (Copilot), CONVENTIONS.md (Aider), AGENTS.md (Codex), or the system prompt field.

  4. Build. The agent edits web/src/App.tsx and supporting files. It knows the SDK, hooks, database API, storage, maps — everything from skills.md.
  5. Deploy.
    git push origin main
    Auto-deploys to my-app.proappstore.online in ~30 seconds via Cloudflare Pages.
The platform context lives at:
https://proappstore.online/skills.md

Drop that URL in your tool's instruction file. The agent fetches it on demand and writes platform-aware code.

What your AI agent gets from skills.md

When an agent reads skills.md, it immediately knows:

  • SDK API — app.db.query(), app.storage.upload(), app.maps.geocode(), app.rooms.join(), all with exact signatures
  • React hooks — useProAuth, useProSubscription, useProGate for auth and subscription gating
  • Project structure — pnpm workspace, web/src/App.tsx entry point, CSS variable tokens
  • Deploy flow — push to main = auto-deploy, no CI config needed
  • Privacy rules — no tracking, no analytics, no third-party scripts
  • Brand — Manrope + Fraunces fonts, purple accent, dark mode via system preference

Example prompt

Build a meetup app where users can create events with a title, date, city, and description. Store events in the database using app.db. Show events on a map using app.maps. Let users RSVP. Add real-time chat per event using app.rooms. Use useProGate for auth. Follow the platform conventions in skills.md.

Workspace layout

Keep all your Pro app repos under one folder:

mkdir -p ~/dev/stores/pas/apps && cd ~/dev/stores/pas/apps
~/dev/stores/pas/ apps/ ← your app repos meetup/ my-app/ platform/ ← SDK, CLI, backend (maintainers only) proappstore/ ← store site (maintainers only)

What makes this different from FreeAppStore

FreeAppStore apps use local storage only. ProAppStore apps get cloud infrastructure:

  • Per-app SQL database — app.db.query('SELECT * FROM events')
  • File storage — app.storage.upload('photo.jpg', file)
  • Maps — app.maps.geocode('Times Square')
  • Uncapped real-time rooms — no connection limits
  • Stripe subscriptions — built-in checkout and billing portal

Same auth system, same deploy flow. The SDK is a superset — @proappstore/sdk includes everything from @freeappstore/sdk plus the Pro modules.
