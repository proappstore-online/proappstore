Documentation

Everything you need to build a Pro app. One SDK, one import, full platform access.

Quick Start

# Install the CLI
npm i -g @proappstore/cli

# Sign in with GitHub
pas login

# Scaffold from the template
pas create my-app
cd my-app

# Develop locally
pnpm dev

# Provision platform resources (Pages, DNS, D1, Data Worker)
pas publish

# Deploy (push to main = auto-deploy)
git push origin main

Your app is live at my-app.proappstore.online. DNS is set up automatically by pas publish.

Other CLI commands

pas whoami            # show signed-in user
pas check             # run compliance checks
pas domain list       # manage custom domains
pas logout            # sign out

React Hooks (recommended)

Hooks give you full control over your UI. Import from @proappstore/sdk/hooks.

useProAuth

Auth state and actions. The primary way to interact with platform identity.

import { useProAuth } from '@proappstore/sdk/hooks'

function App() {
  const { user, loading, signIn, signOut, deleteAccount } = useProAuth(app)

  if (loading) return <p>Loading...</p>
  if (!user) return <button onClick={signIn}>Sign in with GitHub</button>
  return <p>Welcome, {user.login}!</p>
}

useProSubscription

Subscription state. Check if user is a paying subscriber.

import { useProSubscription } from '@proappstore/sdk/hooks'

function Billing() {
  const { subscription, isPro, loading, upgrade, manageBilling } = useProSubscription(app)

  if (!isPro) return <button onClick={() => upgrade()}>Upgrade</button>
  return <button onClick={manageBilling}>Manage billing</button>
}

useProGate

Combined auth + subscription gate. Returns a single gate state.

import { useProGate } from '@proappstore/sdk/hooks'

function App() {
  const { gate, user, signIn, upgrade } = useProGate(app, { allowFree: true })

  if (gate === 'loading') return <p>Loading...</p>
  if (gate === 'signed-out') return <button onClick={signIn}>Sign in</button>
  if (gate === 'no-subscription') return <button onClick={() => upgrade()}>Upgrade</button>
  return <p>Welcome, {user?.login}!</p>
}

Gate states: 'loading' | 'signed-out' | 'no-subscription' | 'ready'

Pass { allowFree: true } to skip the subscription check.

useProNotifications

Web push notification state and actions.

import { useProNotifications } from '@proappstore/sdk/hooks'

function NotifToggle() {
  const { permission, isSubscribed, subscribe, unsubscribe, loading } = useProNotifications(app)

  if (permission === 'denied') return null
  return (
    <button onClick={isSubscribed ? unsubscribe : subscribe}>
      {isSubscribed ? 'Disable' : 'Enable notifications'}
    </button>
  )
}

Auth

GitHub OAuth. Shared identity across all FreeAppStore and ProAppStore apps.

await app.auth.init()                  // Initialize, check for existing session
app.auth.onChange(user => {})          // Listen for sign-in/out
app.auth.signIn()                      // Redirect to GitHub OAuth
app.auth.signIn('google')              // Redirect to Google OAuth
app.auth.signIn('apple')               // Redirect to Apple OAuth
await app.auth.signInWithEmail(email)  // Send magic-link email
app.auth.signOut()                     // Clear session
app.auth.user                          // Current user (or null)
app.auth.token                         // Session token (for API calls)
await app.auth.setDateOfBirth('2000-01-15')  // Set DOB (set-once, age >= 13)

Database (Per-app SQL)

Each Pro app gets its own Cloudflare D1 (SQLite) database. Custom schema, indexes, joins.

// Create tables
await app.db.execute(`
  CREATE TABLE IF NOT EXISTS events (
    id TEXT PRIMARY KEY,
    title TEXT NOT NULL,
    date TEXT,
    city TEXT
  )
`)

// Insert data
const { meta } = await app.db.execute(
  'INSERT INTO events (id, title, date, city) VALUES (?, ?, ?, ?)',
  ['evt-1', 'Meetup', '2026-06-01', 'San Francisco']
)

// Query rows
const { rows } = await app.db.query(
  'SELECT * FROM events WHERE city = ?',
  ['San Francisco']
)

// Batch (transactional)
const results = await app.db.batch([
  { sql: 'INSERT INTO events VALUES (?, ?, ?, ?)', params: ['evt-2', 'Demo', '2026-07-01', 'NYC'] },
  { sql: 'UPDATE events SET title = ? WHERE id = ?', params: ['Updated', 'evt-1'] },
])

// List tables
const tables = await app.db.tables()

Storage (File Upload)

Upload images, videos, documents. Public files get direct URLs. Backed by Cloudflare R2. Limit: 50 MB per file. HTML, JS, and SVG uploads are blocked for security.

// Private upload (owner-only access)
await app.storage.upload('docs/resume.pdf', file, 'application/pdf')

// Public upload (anyone can view the URL)
await app.storage.uploadPublic('avatar.jpg', file, 'image/jpeg')

// Get public URL (no auth needed)
const url = app.storage.publicUrl('avatar.jpg')  // use in <img src>

// Download
const response = await app.storage.download('docs/resume.pdf')

// List files
const files = await app.storage.list()

// Delete
await app.storage.delete('docs/resume.pdf')

KV (Per-user Key-Value)

Simple per-user storage. Each user's data is isolated.

await app.kv.set('profile', { name: 'Alice', theme: 'dark' })
const profile = await app.kv.get('profile')
const keys = await app.kv.list({ prefix: 'note:' })
await app.kv.delete('profile')

Counters (Shared Atomic)

Cross-user counters for votes, views, leaderboards.

await app.counters.increment('page-views')
await app.counters.increment('likes', -1)
const count = await app.counters.get('page-views')
const all = await app.counters.list()

Rooms (Real-time WebSocket)

WebSocket rooms for chat, presence, multiplayer. Backed by Cloudflare Durable Objects. Limits: 32 peers/room, 4 KB/message, 100 msg/s per peer, 24h idle eviction.

const room = app.rooms.join('lobby')

room.send({ type: 'chat', text: 'hello' })
room.onMessage(msg => console.log(msg))
room.onPeers(peers => console.log(peers.length, 'online'))
room.close()

Maps, Geocoding + Routing

Address-to-coordinates, driving directions, and map embeds. OpenStreetMap + OSRM powered. No Google API keys.

// Geocode an address
const results = await app.maps.geocode('Times Square, New York')
// [{lat: 40.758, lng: -73.985, displayName: "Times Square...", address: {...}}]

// Reverse geocode
const place = await app.maps.reverseGeocode(40.758, -73.985)

// Driving route between two points
const route = await app.maps.route(
  { lat: 40.758, lng: -73.985 },
  { lat: 40.748, lng: -73.986 },
)
// route.geometry — GeoJSON LineString
// route.distanceMeters, route.durationSeconds

// Embed map (for <iframe>)
const mapUrl = app.maps.embedUrl(40.758, -73.985)

// Static tile image (for <img>)
const tileUrl = app.maps.staticUrl(40.758, -73.985)

Notifications (Web Push)

Push notifications to your users. Subscribe from the browser, send targeted or broadcast pushes (creator-only).

// User side — subscribe to push
await app.notifications.subscribe()
await app.notifications.unsubscribe()
const subscribed = await app.notifications.isSubscribed()

// Creator side — send to a specific user
await app.notifications.send('user-123', {
  title: 'Event starting!',
  body: 'The meetup begins in 10 minutes.',
  url: '/events/evt-1',
})

// Broadcast to all subscribers
await app.notifications.broadcast({
  title: 'New feature!',
  body: 'Check out the new map view.',
})

// Peer-to-peer: notify another user in the same app (no creator check)
await app.notifications.notifyUser('gh:123', {
  title: '@serge mentioned you',
  body: 'In "Wire the broadcast"',
  url: 'https://kanban.proappstore.online/#/...',
  tag: 'mention:card-1',
})
// Rate-limited: 30/min per user per app

Your app needs a service worker. Use Notifications.getServiceWorkerScript() to generate /sw.js.

Email (Transactional)

Send transactional emails (password resets, confirmations, notifications) via the platform. Resend-backed — no API keys needed. Rate-limited to 100/day per app.

// With reply-to address
await app.email.send(
  'bob@example.com',
  'Reset your password',
  '<p>Click <a href="...">here</a> to reset.</p>',
  { replyTo: 'support@my-app.com' },
)

Webhooks (Outbound)

Receive HMAC-signed HTTP callbacks when events happen in your app. Integrate with Zapier, Make, n8n, or your own backend.

// Register a webhook (app owner only)
const { id, secret } = await app.webhooks.register(
  'notification.sent',
  'https://my-backend.com/webhook',
)
// Save the secret! It's only returned once.

// List registered webhooks
const hooks = await app.webhooks.list()

// Fire a test event
const result = await app.webhooks.test(id)
// { status: 200, body: 'OK' }

// Remove a webhook
await app.webhooks.remove(id)

Supported events: notification.sent, storage.uploaded.

Payloads are POST'd with headers:

HeaderValue
X-Webhook-EventEvent name (e.g. notification.sent)
X-Webhook-SignatureHMAC-SHA256 hex digest of the body, signed with your webhook secret
Content-Typeapplication/json

Manage webhooks visually in the Console under each app's detail page.

AI (Server-side LLM + Embeddings)

Workers AI — text generation, chat, and embeddings included in the platform subscription. No API keys needed. Limits: 16k char prompt, 1,024 max output tokens.

// Text generation ('fast' = Llama-3.1-8B, 'smart' = Llama-3.3-70B)
const { text } = await app.ai.generate('Write a haiku about coding')
const { text } = await app.ai.generate('Summarize...', { model: 'smart', maxTokens: 512 })

// Multi-turn chat
const { text } = await app.ai.chat([
  { role: 'system', content: 'You are a helpful event planner.' },
  { role: 'user', content: 'Suggest a venue for 50 people in SF.' },
])

// Embeddings ('m3' = multilingual 1024-dim, 'base' = English 768-dim)
const { vectors } = await app.ai.embed('yoga class')
const { vectors } = await app.ai.embed(['yoga', 'pilates'], { model: 'base' })

Tenant Scope (Multi-tenant)

Safe-by-default CRUD for multi-tenant tables. Auto-injects tenant_id on writes and auto-scopes reads — prevents cross-tenant leaks.

const tx = app.db.tenant('studio-123')

await tx.insert('clients', { id: 'c-1', name: 'Alice' })
const alice = await tx.find('clients', { id: 'c-1' })
const all = await tx.findMany('clients')
const count = await tx.count('clients')
await tx.update('clients', { id: 'c-1' }, { name: 'Alicia' })
await tx.delete('clients', { id: 'c-1' })

Tables must have a tenant_id TEXT column. Drop to app.db.query() for joins or aggregates.

Roles (App-level RBAC)

Per-app role management. Default roles out of the box: owner (automatic, app creator), member (basic access), moderator, editor, viewer. Custom roles are supported — pass any string.

// Assign a role
await app.roles.assign('user-456', 'moderator')

// Revoke a role
await app.roles.revoke('user-456', 'moderator')

// Check if the current user has a role
const isMod = await app.roles.check('moderator')

// List all roles for the current user
const myRoles = await app.roles.myRoles()
// ['member', 'moderator']

// List all role assignments for the app (owner-only)
const all = await app.roles.listAll()
// [{ userId: 'user-456', role: 'moderator' }, ...]

Proxy (Secret-injecting API Proxy)

Call third-party APIs without exposing keys to the client. Limits: 10k requests/day, 100 KB request/response body, 5 secrets per app.

const response = await app.proxy.fetch('/openai/chat/completions', {
  method: 'POST',
  body: JSON.stringify({ model: 'gpt-4', messages: [...] }),
})

Usage Tracking

ProAppStore tracks usage automatically to compute creator payouts. Auto-started by initPro() — you don't need to do anything.

// Default — telemetry on
const app = initPro({ appId: 'my-app' })

// Opt out (won't count toward payouts)
const app = initPro({ appId: 'my-app', usage: { auto: false } })

// Manual controls (rarely needed)
app.usage.start()
app.usage.stop()
app.usage.flush()

Agent Teams (AI-powered development)

Every PAS project can have a team of AI agents that build, review, and test your app. Agents run on Anthropic and OpenAI infrastructure — PAS provides the coordination layer, ticket board, and project tools.

How it works

  1. PO creates a ticket with a raw idea ("Build a chess academy with game rooms and puzzles")
  2. BA agent refines it into a structured spec with acceptance criteria
  3. PO approves the spec
  4. Dev agent writes the code using PAS SDK, commits to GitHub
  5. QA agent writes vitest unit + integration tests from the acceptance criteria
  6. If tests fail in CI, it loops back to Dev (max 5 iterations)
  7. When tests pass and CI is green, the app deploys automatically

Ticket lifecycle (kanban)

inbox → ba-refining → awaiting-approval → ready → dev-active → qa-active → deploying → done
                                                                 ↑              ↓
                                                                 └―― qa-failed ――┘

deploying is an automatic system stage (push → verify the CI build for that commit), not an agent action.

Each project gets its own kanban board in the console. Tickets transition automatically as agents complete their work. PO approves specs and can cancel tickets at any point.

Three agent roles

Testing strategy (two layers)

LayerLocationToolWho writesWhen it runs
Unit + integrationtests/unit/*.test.ts, tests/integration/*.test.tsxvitestQA agent (Build pipeline)CI on every push
End-to-ende2e/specs/*.spec.tsPlaywrightQA agent (Test tab)On demand from Test tab

The Build pipeline QA writes fast vitest tests (pure-function unit tests + jsdom component tests via @testing-library/react). These run in CI in seconds and gate the deploy. The Test tab's QA writes Playwright E2E specs against the live app — slower, more expensive, run on demand.

Board controls

The Build board header has inline controls for the entire agent team:

  • Model per role — set each agent (BA/Dev/QA) to a different model (Haiku/Sonnet/Opus/GPT-4o) with one-click presets (Cheap/Balanced/Smart)
  • Run timeout — 5-60 min per agent turn (prevents runaway cost on large tasks)
  • Monthly cost cap — $10-$1000 auto-pause threshold
  • Max output tokens — per role (2k-32k)
  • Live cost badge — real-time $ + token count, flashes on change
  • Deploy banner — live timer + build history with pass/fail

Cost controls & Spending tab

Each project has a monthly cost cap (default $50). Token spend is tracked per ticket, per role, per model. When the cap is reached, active tickets auto-fail. Agents use your BYO API key (Anthropic or OpenAI) — ProAppStore charges nothing on top.
